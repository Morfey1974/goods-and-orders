# WEB Order Management — учёт заказов (עוסק פטור)

Веб-приложение для малого бизнеса в Израиле: клиенты, поставщики, закупки (приходные накладные), каталог с группами товаров, склад, документы продаж (הצעת מחיר → הזמנת לקוח → חשבון חיוב → קבלה), складские отчёты PDF, профиль עוסק פטור.

Подробный план: [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md)  
Склад FIFO / себестоимость: [docs/INVENTORY_COSTING_PLAN.md](docs/INVENTORY_COSTING_PLAN.md)  
Доп. расходы в закупках: [docs/LANDED_COST.md](docs/LANDED_COST.md)  
Палитра цветов: [docs/color-palette.html](docs/color-palette.html)

**Удалённый репозиторий:** https://github.com/Morfey1974/goods-and-orders

## Быстрый старт

### 1. Клонировать и запустить API + БД (Docker)

```powershell
git clone https://github.com/Morfey1974/goods-and-orders.git
cd goods-and-orders

copy .env.example .env   # опционально: JWT_SECRET

docker compose up -d --build
```

Дождитесь готовности (30–60 с). **Миграции БД применяются автоматически** при старте API.

| Сервис | URL |
|--------|-----|
| API | http://localhost:8080 |
| Swagger | http://localhost:8080/swagger |
| Health | http://localhost:8080/api/health |
| PostgreSQL | `localhost:5432` — `ordermgmt` / `ordermgmt_dev` / `ordermgmt` |

### 2. Фронтенд

В **новом** окне PowerShell:

```powershell
cd src\order-management-web
npm install
npm run dev
```

| Сервис | URL |
|--------|-----|
| Веб-интерфейс | http://localhost:5173 |

Прокси `/api` → `http://localhost:8080` задан в `vite.config.ts`.

### 3. Первый вход

1. http://localhost:5173 → **Регистрация**  
2. **Настройки** — профиль, контакты, банк, логотип, подпись, PDF для клиентов  
3. Язык: עברית / Русский / English (RTL для иврита)

**Сброс пароля:** на странице входа — «Забыли пароль?» → письмо со ссылкой (при `Email:Enabled: false` ссылка пишется в лог API). В `appsettings.json` задайте `App:FrontendBaseUrl` (URL фронтенда для ссылки сброса).

## После обновления кода (`git pull`)

Обязательно **пересоберите контейнер API** (новые миграции и эндпоинты):

```powershell
docker compose up -d --build api
```

Новые миграции БД (применяются при старте API):

- `ReceiptPaymentLines` — строки оплаты в קבלה
- `Tenant.WithholdingTaxPercent` — % ניכוי במקור по умолчанию
- `CustomerContacts` — контакты клиента для email
- `PasswordResetTokens` — одноразовые токены сброса пароля
- `Suppliers`, `SupplierContacts`, `PurchaseReceipts`, `PurchaseReceiptLines` — поставщики и приходные накладные
- `AddProductTrackInventory` — флаг учёта остатков по товару
- `SyncProductGroupsModel` — группы товаров (`ProductGroups`, `ProductGroupMembers`)
- `AddInventoryCosting` — партии FIFO, средняя WAC, метод оценки в настройках
- `AddProductWarehouseId` — склад по умолчанию в карточке товара
- `DocumentNumberByTypeAndPlainNumbers` — номера документов **без префикса** (377, 40051, 80036)
- `SetTrackInventoryDefaultFalse` — по умолчанию «Учитывать на складе» = **Нет** (для поэтапной корректировки остатков)
- `AddPurchaseReceiptLandedCosts` — доп. расходы (таможня, логистика) в приходных накладных
- `AddPurchaseReceiptDocuments` — **несколько вложений** PDF/изображений на одну накладную
- `ClearLegacyPurchaseReceiptDocumentFields` — перенос старого одиночного вложения в таблицу документов
- `AddPurchaseReceiptUsdIlsRate` — **свой курс USD→ILS** в черновике приходной накладной (иначе — курс Банка Израиля на дату документа)
- `AddPurchaseReceiptLineTotal` — **сумма строки** в валюте накладной (`LineTotal`); точность `UnitPrice` до 6 знаков (исправляет округление USD при сохранении)
- `AddTenantBackupFields` — настройки резервного копирования (путь, статус последней копии)
- `AddBusinessExpensesAndFixedAssets` — журнал бизнес-расходов (дом / офис), legacy-таблица `FixedAssets`
- `AddExpenseLocationMode` — режим «дом / смешанный» для расходов
- `AddBusinessExpenseDocuments` — вложения к записям журнала расходов
- `AddFixedAssetVendorName`, `AddFixedAssetDocuments` — поля legacy ОС (миграция данных)
- `AddFixedAssetInstancesAndProductTypes` — типы товаров **FA** (основное средство) и **CM** (расходник), экземпляры ОС из накладных GR, авторасходы CM
- `ReclassifyQuoteSentAsOpen` — הצעות מחיר со статусом **Открыто** (не «Отправлено») до реальной отправки по email
- `AddQuoteClientOrderFields` — **הזמנת לקוח** на הצעת מחיר: дата, № PO, файл PDF/изображение
- `AddStockAssembly` — **сборка на складе** (`StockAssemblies`, `StockAssemblyLines`, `AssemblyRecipeLines` в карточке FG)
- `AddReceiptChargeAllocations` — **несколько חשבונות חיוב на одну קבלה** (таблица связей + перенос существующих квитанций)

При старте API дополнительно: перенос остатков/партий/WAC на системный склад по типу товара и **пересчёт «остатка после»** в движениях по дате документа.

Фронтенд при изменениях UI:

```powershell
cd src\order-management-web
npm install
npm run dev
```

## Настройки (две вкладки)

| Вкладка | Содержание |
|---------|------------|
| **Настройка бизнеса** | Профиль, контакты, брендинг, PDF для клиентов, нумерация документов, сброс склада, банк |
| **Настройка программы** | **Резервное копирование** — полный ZIP, выбор папки, статус последней копии |

### Настройка бизнеса — разделы

| Раздел | Содержание |
|--------|------------|
| Общие данные | Название, ת.ז., עוסק, категория, адрес, **% ניכוי במקור**, **метод оценки склада** (FIFO / WAC) |
| Контакты | Email (редактируемый), телефоны, сайт, язык |
| Логотип и подпись | JPG/PNG/WebP → PDF הצעת מחיר и другие документы; **просмотр образца** документа с брендингом |
| Документы для клиентов | PDF: אישור חשבון, כרטיס חברה, ניהול ספרים, ניכוי מס — загрузка и **отправка по email** |
| **Нумерация документов** | Следующий номер для הצעה / חשבון / קבלה — **без префикса**, как в YeshInvoice (внутренний счётчик «заказ» скрыт) |
| **Сброс складских данных** | Удаление всех движений, остатков и партий FIFO/WAC (товары и склады сохраняются); для повторного ввода начального מלאи |
| **Настройка программы → Резервное копирование** | Кнопка **«…»** — выбор папки (LocalScanLauncher); **«Сохранить путь»** пишет `BACKUP_HOST_PATH` в `.env` и перезапускает API; **«Сделать резервную копию»** — ZIP с `database.sql`, `uploads/`, `KAK_VOSSTANOVIT.txt`; подпапка **ДДММГГ-ЧЧ ММ** и метка времени в имени ZIP — **по часовому поясу Израиля** (как колонка «Когда» в UI) |
| Банковские реквизиты | Код банка (справочник IL), филиал, счёт, SWIFT/ABA/IBAN |

Файлы хранятся в каталоге **`data/uploads/`** на хосте (монтируется в контейнер API как `/app/uploads`; при локальном запуске API без Docker — `Uploads:Path` в `appsettings.Development.json`).

### Резервное копирование и восстановление

1. **Настройки** → **«Настройка программы»** → **«…»** — выберите папку → **«Сохранить путь»**.
2. **«Сделать резервную копию сейчас»** — в папке появится подкаталог **ДДММГГ-ЧЧ ММ** (например `100626-19 32`) с ZIP-архивом.
3. В архиве: `database.sql`, `uploads/`, `KAK_VOSSTANOVIT.txt`, `manifest.json`.
4. Ручной бэкап: `powershell -File scripts\backup-all.ps1` (контейнеры должны быть запущены).
5. Перезапуск помощника выбора папки: `scripts\restart-local-helper.bat`.

Переменная `.env`: `BACKUP_HOST_PATH` — путь на диске Windows (монтируется в контейнер API как `/app/backups`). После смены: `docker compose up -d api`.

## Поставщики и закупки

| Возможность | Описание |
|-------------|----------|
| **Поставщики** | Справочник с международными полями (страна ISO, VAT, валюта, банк, адрес), карточка поставщика |
| **Приходные накладные** | Поставщик, дата, № инвойса, валюта (USD/ILS), строки товаров, **несколько вложений** PDF/изображение (инвойс, декларация, чек и т.д.) |
| **Доп. расходы (landed cost)** | Таможня, логистика, налог — пропорционально на **все** строки (склад, FA, CM, SV); доля SV — в операционные (логистика); см. [docs/LANDED_COST.md](docs/LANDED_COST.md) |
| **Курс USD/ILS** | Автоподстановка курса Банка Израиля на дату документа (`GET /api/exchange-rates/usd-ils`); опционально **«Свой курс USD»** — сохраняется в черновике и **фиксируется при оприходовании** |
| **Суммы в ₪ (отчёты и списки)** | Для USD-накладных в отчётах и итогах списка используется **снимок в шекелях** (`UnitCostIls × кол-во` после проведения или `LineTotal × курс` в черновике), а не сумма в долларах «как ₪» |
| **Итоги по строкам** | В подвале таблицы — **Итого $** и **Итого ₪** в соответствующих колонках; **сумма строки в USD/ILS** сохраняется в БД (`LineTotal`) — без потери копеек при перезагрузке |
| **Список закупок** | Для накладных в USD — **₪ основная сумма** и **USD вторичной строкой**; **сортировка по колонкам** (клик по заголовку ⇅/▲/▼), **запоминается в браузере**; **поиск** по №, поставщику и статусу; фильтры по поставщику, статусу и датам |
| **Вложения** | Несколько PDF/изображений на накладную; полоска переключения; предпросмотр в iframe; **«Добавить со сканера»** (NAPS2 + LocalScanAgent через launcher); в списке — 📎 × количество. На **новой** накладной файлы сначала в отложенном списке и загружаются при сохранении или оприходовании |
| **Сумма строки при оприходовании** | Достаточно **суммы в USD** или **₪/ед.** (ручной ввод в шекелях, напр. для услуги доставки) |
| **Черновик** | Кнопка **«Сохранить документ»** сохраняет черновик (без движения по складу); на новой накладной открывается карточка с присвоенным номером |
| **Оприходование** | Кнопка **«Оприходовать»** сохраняет черновик, проводит товары на склады (движения `Receipt`), **создаёт экземпляры ОС (FA)** и **расходы (CM)**, закрывает редактор и возвращает в список «Закупки»; перед проведением — подтверждение |
| **Типы FA / CM / SV** | **FA** — ОС без склада; **CM** — расходник в журнал; **SV/CH** (доставка, подписки) — в журнал операционных расходов, не в COGS |
| **Landed cost** | Распределяется на склад, **FA**, **CM** и **SV**; откат накладной в черновик для перепроведения (`RevertPostedToDraft`) |
| **Обязательные поля** | Поставщик; в каждой строке — **склад** (для товаров со складским учётом) и **цена закупки** > 0; для **FA** — категория амортизации в карточке товара |
| **Выбор товаров** | Модальное окно по образцу מחירון: фильтры в шапке, отметка строк, **Enter в поле количества** — выбор строки без закрытия окна; **Сохранить** добавляет позиции в накладную |
| **Несохранённые изменения** | При уходе со страницы без сохранения — диалог (сохранить черновик / не сохранять / отмена); при успешном сохранении диалог не показывается; диалог **поверх** вложенных модалок (карточка товара из пикера) |

Склад в строке: для товаров с учётом остатков нужно выбрать конкретный склад (не «По типу товара»). Услуги, **FA** и **CM** — склад не требуется (подсказка в колонке склада).

Эндпоинты:

- `GET/POST/PUT/DELETE /api/suppliers`, `GET /api/suppliers/{id}`
- `GET/POST /api/purchase-receipts`, `GET/PUT/DELETE /api/purchase-receipts/{id}`
- `POST /api/purchase-receipts/{id}/post` — оприходование на склад (вызывается из UI кнопкой «Оприходовать»)
- `POST/GET/DELETE /api/purchase-receipts/{id}/documents/{documentId?}` — вложения (несколько файлов на накладную)
- `POST/DELETE /api/purchase-receipts/{id}/document` — legacy-эндпоинт одиночного вложения (совместимость)
- `GET /api/exchange-rates/usd-ils?date=` — курс USD→ILS на дату

Миграции: `AddSuppliersAndPurchaseReceipts`, `AddProductTrackInventory`, `AddPurchaseReceiptLandedCosts`, `AddPurchaseReceiptDocuments`, `AddPurchaseReceiptUsdIlsRate`, `AddPurchaseReceiptLineTotal`.

## Каталог товаров

| Возможность | Описание |
|-------------|----------|
| **Группы товаров** | Справочник групп на странице «Товары и услуги»; фильтр и привязка товаров к группам (мультивыбор в карточке); **«Добавить группу»** в выпадающем списке (Enter не закрывает карточку товара); удаление группы — **ConfirmDialog**; модалка групп растягивается по высоте окна |
| **Тип / вид** | Типы **CP, FG, SV, CH, BD, SP, FA, CM**; учёт остатков по флагу `trackInventory` (по умолчанию **выключен**) |
| **Основные средства (FA)** | Категория амортизации (פחת) и **% для бизнеса**; экземпляр ОС создаётся при оприходовании накладной GR |
| **Расходники (CM)** | Списываются в журнал расходов при оприходовании накладной |
| **Карточка товара** | Редактирование **цены продажи**, групп, склада; для **FG/BD** — **состав (BOM)**: модальное окно выбора CP/SP (как в накладных), в пикере — маркер **«В составе»** для уже добавленных позиций; таблица артикул / наименование / количество; для **FG** с учётом остатков — вкладка **«Рецепт сборки»** (компоненты на 1 готовое изделие, используется при сборке на складе); для FA — блок амортизации; вкладки **«Партии FIFO»** (приход / остаток / сумма прихода; **все партии**, включая полностью списанные) и **«Движения склада»** (дата — **дата документа**, остаток после — по хронологии дат); в партии FIFO — ссылка на документ **сборки** (если партия создана сборкой); **«Сохранить»** не закрывает окно |
| **Таблица каталога** | Клик по **артикулу** → карточка; отображение **legacySku**; **ширина колонок** перетаскиванием (сохраняется в браузере); единая **панель списка** (см. ниже) |

Эндпоинты: `GET/POST/PUT/DELETE /api/product-groups`, `PUT /api/product-groups/{id}/members`.

Миграции: `SyncProductGroupsModel`, `AddProductWarehouseId`, `SetTrackInventoryDefaultFalse`.

## Списки и таблицы (`DataTablePanel`)

На вкладках **Главная** (незавершённые документы), **Клиенты**, **Поставщики**, **Товары и услуги**, **Закупки**, **Документы**, **Сборка**, **Склад**, **Журнал расходов**, **Оценка склада** и финансовые отчёты используется общий компонент `DataTablePanel`:

| Возможность | Описание |
|-------------|----------|
| **Единая панель** | Заголовок («Клиенты 10 результатов»), фильтры, таблица и пагинация — **один resizable-блок**; тянется за **три полоски** в правом нижнем углу панели |
| **Симметричное расширение по ширине** | Панель центрируется; ширина растёт **от центра в стороны** (2× горизонтальный ход курсора) |
| **Высота вниз** | Верх панели закреплён; тянуть вниз — увеличивается только нижний край (максимум — до низа окна) |
| **Ширина до края страницы** | Максимум — ширина рабочей области (не обрезается на половине экрана) |
| **Колонки** | Перетаскивание границ заголовков; значения по центру (кроме названия/товара/клиента); на **Закупках** — сортировка по клику на заголовок (сохраняется в `localStorage`) |
| **Пагинация** | 25 / 50 / 100 / 200 строк; выбор размера страницы сверху и снизу |
| **Оформление** | Скруглённые поля фильтров; шапка и строки таблицы — отдельные блоки с зазором; **подсветка строки** при наведении |

Файлы: `src/order-management-web/src/components/ui/DataTablePanel.tsx`, стили `styles/data-table-panel.css`, ключи размеров в `lib/resizablePanelKeys.ts` (`localStorage`).

## Склад и отчёты

| Возможность | Описание |
|-------------|----------|
| Склад | Остатки по складам; **артикул + старый מק"ט** в таблице; **поиск** по артикулу и названию; приход, движения; **та же панель списка**, что и на других вкладках |
| **Себестоимость** | FIFO (партии) или WAC (средняя) — в настройках; закупочная цена в **приходных накладных** и **начальном остатке** (`unitCostIls`); **цена продажи** — в карточке товара (`unitPrice`) |
| **Начальный остаток** | Склад → **«Начальный מלאי»**; черновик в `localStorage`; оприходование создаёт партии FIFO (перенос из YeshInvoice / PDF) |
| **Партии FIFO** | Вкладка в карточке товара: колонки **приход** (изначальное кол-во), **остаток**, сумма прихода; полностью списанные партии видны с остатком 0; API `GET /api/inventory/lots?includeDepleted=true`; для партий от **сборки** — номер ASM и ссылка на карточку сборки |
| **Сборка на складе** | Вкладка **«Сборка»**: выпуск FG из комплектующих (списание CP по FIFO, оприходование готовой продукции); черновик / **«Оприходовать»**; кол-во компонентов в таблице — **на 1 готовое изделие**; рецепт из карточки FG или ручной ввод; номер ASM-00001… |
| Движения | История с **себестоимостью ₪**; **остаток после** пересчитывается по **дате документа** (`MovementDate`), не по порядку проведения; при старте API — автоисправление; отчёт PDF |
| **Смешанный текст в PDF** | Иврит + латиница/цифры/₪ — корректный порядок в подзаголовках и суммах (`PdfReportFormat`, `RenderReportSubtitle`); шрифты `NotoSansHebrew` + `NotoSans` |
| **PDF отчётов (единый UX)** | На странице отчёта — только **«Просмотр PDF»**; в модалке — **«Сохранить PDF»** (диалог «Сохранить как», **имя файла на иврите**, без автозагрузки в «Загрузки»); отмена диалога — файл **не** сохраняется |
| **Отчёты** (вкладка «Отчёты») | PDF с шапкой бизнеса; подвкладка **«Финансы»** запоминается при возврате; отчёты: доходы, закупки, COGS, валовая прибыль, **прибыль/убыток**, операционные расходы, **услуги поставщиков**, **טופס 1342** |
| Остатки / движения PDF | Фильтры по складу и периоду; **«Просмотр PDF»** (без отдельной кнопки скачивания на странице) |
| **Доходы за период** | Проведённые קבלות, строки оплаты по дате (кассовый метод); фильтр дат как в YeshInvoice (быстрые кнопки + выпадающий список); **«Просмотр PDF»** |
| **Расходы за период** | Оприходованные **складские** закупки (GR) по дате документа — **без FA/CM/SV**; суммы **в ₪**; PDF: **דוח הוצאות** в имени файла; **«Просмотр PDF»** |
| **COGS / валовая прибыль** | **COGS (списания)** — только по **проведённым** חשבונות חיוב; отчёт **Себестоимость (COGS)** — **«Просмотр PDF»**. **Валовая прибыль** и **P&L** — **кассовый метод** |
| **Прибыль и убыток** | Доход − COGS − операционные расходы; **выбор метода COGS** (касса / формула מלאי / списания H-); **«Просмотр PDF»** |
| **Оценка на дату** | Остатки и COGS на **прошлую дату** (напр. 31.12.2024) учитывают списания **после** этой даты — конечный מלאי не «утекает» в более ранний период |
| **Оценка склада** | Отчёты → стоимость остатков; опция **«Детализация по партиям FIFO»**; **«Просмотр PDF»**; таблица в `DataTablePanel` |
| **Операционные расходы** | Журнал расходов + амортизация ОС за период; **«Просмотр PDF»** |
| **Услуги поставщиков** | Landed cost и строки SV/CH из GR; **фильтры** (поиск, поставщик, источник, категория, даты); **«Просмотр PDF»** |
| **טופס 1342** | Ведомость ОС за **налоговый год**; **«Просмотр PDF»** |
| **Landed cost на GR** | Доп. расходы (налог, таможня, логистика) распределяются на **все** строки (товар, FA, CM, SV); доля SV — в операционные (логистика) |
| **Нехватка при проведении חשבון** | Перед списанием проверяются все строки и **компоненты BOM**; учитываются партии FIFO **на всех складах**; в ошибке — **артикулы** (CP-…), а не UUID |

Количества — **целые числа**. В движениях и партиях себестоимость в **₪**.

## Документы

**Цепочка продаж:** הצעת מחיר → **הזמנת לקוח** (файл на котировке) → חשבון חיוב → קבלה. Отдельная вкладка «Заказы» в UI **убрана**; закупочные הזמנות — только в потоке поставщиков.

| Тип | PDF / UI |
|-----|----------|
| הצעת מחיר (Quote) | PDF: баннер «לפרויקט …» (иврит + латиница в правильном порядке); статус **Открыто** до отправки по email; в мастере — блок **הזמנת לקוח** (дата, №, файл) |
| חשבון חיוב (Charge) | Тот же макет; баннер: «יצא מתוך הצעת מחיר מס׳ … \| לפרויקט …» (длинный текст **переносится**); без родительской הצעה — текст из **описания** документа |
| קבלה (Receipt) | Баннер: «על בסיס חשבון חיוב מס׳ …»; **таблица строк оплаты** (תאריך, סוג תשלום, פירוט, סה״כ), не позиции счёта |

В PDF колонка **פירוט**: **артикул / название** (не legacy מק״ט), порядок RTL для смешанного текста.

**Нумерация:** номера **без префикса** (377, 40051, 80036) — как в YeshInvoice; счётчики в **Настройки → Нумерация документов**.

**Импорт из YeshInvoice:** кнопка **«Импорт CSV»** на странице «Документы» — экспорт הצעה / חשבון / קבלה; клиент по עוסק/שם; связи quote↔charge↔receipt по тексту в описании; склад при импорте **не списывается**.

**Удаление:** каскадное — при удалении הצעה удаляются связанные חשבון и קבלה (с подтверждением).

### קבלה — редактор оплаты

- Вкладки: ניכוי במקור, העברה בנקאית, צ׳ק, כרטיס אשראי, אפליקציה, PayPal, מזומן, אחר.
- Каждая строка — **«Сохранить строку»**, затем **«Сохранить черновик»** (можно открыть PDF без выпуска) или **«Выпустить קבלה»**; **«Сохранить черновик»** без строк оплаты сохраняет **дату и описание** (дата — календарный день без сдвига по часовому поясу); после сохранения черновика **форма не сбрасывается** — дата депозита, строки оплаты и введённые реквизиты сохраняются.
- **Несколько счетов** — блок **«Связанные счета»** (номера и суммы) справа от полей **Дата** / **Валюта**; описание автоматически: «יצא מתוך חשבונות עסקה מספר …»; **один счёт** — описание из счёта, компактные поля даты и валюты.
- % ניכוי במקור подставляется из настроек бизнеса; сумма банковского перевода пересчитывается автоматически.
- **Банковский перевод** — реквизиты **банка клиента** (не עוסק), из карточки לקוח.
- **«Просмотр PDF»** / **«Отправить по email»** в подвале мастера (email — заглушка до SMTP).

### Список документов

- **Фильтры:** поиск, тип, **клиент** (`?customerId=`), статус.
- Отдельные колонки **№** и **Статус** (бейджи одной ширины, подписи на языке интерфейса: ru / en / he).
- **Мультивыбор счетов** — галочки у открытых **חשבונות חיוב** (колонка участвует в изменении ширины таблицы); кнопка **«Создать квитанцию»** (только если все выбранные счета **одного клиента**); сумма квитанции = сумма счетов; при проведении оплата должна **точно** совпадать с этой суммой; каждый счёт закрывается.
- Колонка **הזמנה** — овальный бейдж, если к הצעת מחיר прикреплена הזמנת לקוח.
- Клик по номеру — превью PDF. Кнопки **+** (выпуск חשבון חיוב / קבלה) и **⋮** (действия) — **только одно меню** открыто; после «Сохранить черновик» список обновляется без F5.

### Мастер הצעה / חשבון חיוב / קבלה

- Создание без отдельного окна выбора клиента: **клиент** (или **חשבון חיוב** для קבלה) — в шапке карточки, как поставщик в приходной накладной.
- **«Сохранить черновик»** — без закрытия, статус **Черновик**; **«Сохранить и выйти»** — проведение (**Открыт** для הצעה/חשבון, **Закрыт** для קבלה). Склад **списывается только при проведении** חשבון חיוב; при возврате в черновик или удалении счёта списание **откатывается**.
- **Черновик חשבון חיוב** с родительской הצעת מחיר: при **открытии** документа строки и скидка **подтягиваются из הצעה** (пока счёт не проведён) — можно править הצעה и вернуться к черновику счёта.
- **Текстовые строки** (без товара) — кнопка **«Добавить строку»**; на חשבון חיוב не списывают склад; в PDF попадают как обычные позиции.
- Пикер товаров — тот же компонент, что в приходных накладных (поиск, фильтры, сброс при открытии).
- **Отмена** / **×** — с подтверждением **только при несохранённых изменениях**. Enter в полях даты **не** закрывает окно. Общий компонент **DateInput** в отчётах и формах.
- Поле **цены за ед.** в строках — можно очистить и ввести новое значение (не залипает на «0»).
- Полноэкранные мастера, **запоминание размера** (`localStorage`). В шапке PDF и email — **עוסק פטור** (не «פטור עוסק»).

Для баннера חשבון חיוב укажите **הצעת מחיר** как родительский документ (`parentDocumentId` при создании).

## Email (SMTP) — пока заглушка

В `src/OrderManagement.Api/appsettings.json`:

```json
"Email": {
  "Enabled": false
},
"App": {
  "FrontendBaseUrl": "http://localhost:5173"
}
```

При `Enabled: false` кнопка «Отправить файлы по email» **не шлёт письмо**, а показывает сообщение о режиме заглушки (запрос логируется на сервере). То же для **сброса пароля** — ссылка `/reset-password?token=…` выводится в лог API.  
Когда будут данные SMTP — установите `Enabled: true` и заполните `SmtpHost`, `SmtpPort`, `SmtpUser`, `SmtpPassword`, `FromAddress` (реализация отправки в `TenantEmailService` и `PasswordResetMailer`).

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| Ошибка при загрузке PDF / 404 на `/api/tenant/assets` | `docker compose up -d --build api` |
| `Only PDF files are allowed` при корректном PDF | Обновите API (см. выше); допускается `application/octet-stream` |
| Docker не стартует | Запустите Docker Desktop |
| API недоступен | `docker compose ps` — сервис `api` Up |
| CORS | Добавьте origin в `Cors:Origins` в `appsettings.json` |
| Порт 5432 занят | Смените порт в `docker-compose.yml` или остановите другой PostgreSQL |
| PDF не открывается / кириллица в отчёте | Пересоберите API (`docker compose up -d --build api` из корня проекта); в `Assets/Fonts/` нужны `NotoSansHebrew-*.ttf` и `NotoSans-*.ttf` |
| Иврит в PDF «перемешан» (не как в UI) | Пересоберите API — см. выше; после обновления заново скачайте отчёт (не старый PDF из кэша) |
| Отчёт по движениям — Internal Server Error при выборе дат | Пересоберите API (`docker compose up -d --build api`); нужна нормализация дат UTC |
| Список закупок — Internal Server Error при фильтре по датам | То же — фильтр `from`/`to` через UTC (`ReportDateRange`) |
| «Добавить со сканера» — ошибка связи | Запустите `scripts\start-scan-agent.bat` или ярлык «Запуск учёта заказов»; нужны NAPS2 и .NET SDK |
| Модальное окно закрывается при ресайзе | Обновите фронтенд — используется `AppModal`, не сырой `onClick` на overlay |
| Ошибка concurrency при сохранении накладной | `docker compose up -d --build api`; обновите страницу и сохраните снова |
| Кнопка «Сохранить документ» неактивна | Заполните поставщика, склад и цену закупки во всех строках |
| Не добавляется вложение к накладной | Перезапустите фронт (`npm run dev` на порту **5173**); проверьте вкладку Network — `POST …/documents` |
| Сайт не открывается (localhost:5173) | Запустите `scripts\start-web.bat` или `npm run dev` в `src\order-management-web` |
| PDF не открывается / Internal Server Error в превью документа | Пересоберите API; длинный баннер в PDF должен переноситься (не `Row` без wrap) |
| Не проводится חשבון חיוב — «Insufficient stock» | В сообщении указаны **артикулы** (CP-… / FG-…); для FG с BOM проверьте остатки **комплектующих**; пополните склад или уменьшите количество |
| Черновик חשבון не совпадает с обновлённой הצעה | Закройте и снова откройте черновик — строки подтягиваются при `GET /api/documents/{id}` |
