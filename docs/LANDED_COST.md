# Landed cost: таможня, логистика, налоги на приходной накладной

Документ описывает модель данных, UX и отчёты для **полной себестоимости товара** (landed cost) при импортных закупках.

**Статус:** фазы 1–3 реализованы (модель, API, распределение при Post, UI). Отчёты — фаза 4–5.
**Связано с:** [INVENTORY_COSTING_PLAN.md](./INVENTORY_COSTING_PLAN.md)

---

## 1. Бизнес-задача

Пример: закупка в Китае + инвойс $150 (товар + международная доставка) + в Израиле FedEx выставляет **228 ₪** (таможня, оформление).

| Требование | Решение |
|------------|---------|
| Правильная **₪/ед.** в FIFO | Распределить все доп. расходы на строки **товара** при оприходовании |
| Разные поставщики услуг | FedEx, брокер, DHL — каждая строка расхода со **своим** `supplierId` |
| Отчёт «услуги FedEx за период» | SUM по `PurchaseReceiptLandedCostLines` WHERE `SupplierId = FedEx` |
| Отчёт «закупки у поставщика X» | SUM по **товарным** строкам WHERE `PurchaseReceipt.SupplierId = X` |

**Не смешивать** с каталогом услуг SV/CH: строки landed cost — не отдельные «товары», а **расходы, привязанные к этой накладной**, которые увеличивают себестоимость партии.

## 2. UX приходной накладной

### Блок «Товарные строки» (как сейчас)

Поставщик накладной = **кто продал товар** (китайский завод).  
Колонки: товар, склад, кол-во, сумма USD / ₪, ₪/ед.

### Блок «Доп. расходы (налоги / таможня / логистика)»

- Галочка **«Учесть доп. расходы на себестоимость»** — показывает/скрывает блок (данные сохраняются в черновике).
- Таблица строк:

| Поле | Описание |
|------|----------|
| **Поставщик услуги** | Выбор из справочника поставщиков (FedEx, брокер, …) |
| **Категория** | Логистика / Таможня / Налог / Прочее |
| **Сумма** | В **USD** или **ILS** (переключатель в строке или общий с документом) |
| **Примечание** | Необязательно (номер счёта FedEx) |

Кнопка «+ Добавить расход».

### При оприходовании (Posted)

1. По каждой **товарной** строке со складом считается базовая сумма в ₪: `baseLineIls = unitCostIls × qty`.
2. Все строки landed cost переводятся в ₪ (`amountIls`; для USD — курс на **дату документа**, как у товарных строк).
3. `totalLandedIls` = сумма всех строк доп. расходов.
4. **Распределение** на товарные строки **пропорционально `baseLineIls`** (если база 0 — поровну по количеству).
5. Итоговая `unitCostIls` строки = `(baseLineIls + allocatedShare) / qty` → в FIFO-партию.

Строки landed cost **не создают** движений склада; они только участвую в расчёте и **хранятся для отчётов**.

## 3. Модель данных

### `PurchaseReceiptLandedCostLine`

| Поле | Тип | Назначение |
|------|-----|------------|
| `Id` | Guid | PK |
| `PurchaseReceiptId` | Guid | FK накладной |
| `SupplierId` | Guid | **Поставщик услуги** (FedEx и т.д.) |
| `Category` | enum | Logistics, Customs, Tax, Other |
| `Currency` | string(3) | USD / ILS |
| `Amount` | decimal | Сумма в валюте строки |
| `AmountIls` | decimal? | Зафиксировано при Post (для отчётов) |
| `Notes` | string? | Номер счёта, комментарий |
| `SortOrder` | int | Порядок |

### Связи для отчётов

```
PurchaseReceipt
  ├── SupplierId          → поставщик ТОВАРА (отчёт закупок)
  ├── Lines[]             → товарные строки (закупки, FIFO)
  └── LandedCostLines[]   → доп. расходы (отчёт услуг по поставщику услуги)
        └── SupplierId    → FedEx, брокер, …
```

## 4. Будущие отчёты (SQL-логика)

### Услуги / логистика по поставщику за период

```sql
SELECT s.Name, SUM(l.AmountIls)
FROM PurchaseReceiptLandedCostLines l
JOIN PurchaseReceipts r ON r.Id = l.PurchaseReceiptId
JOIN Suppliers s ON s.Id = l.SupplierId
WHERE r.TenantId = @tenant
  AND r.Status = 'Posted'
  AND r.DocumentDate BETWEEN @from AND @to
GROUP BY s.Id, s.Name;
```

### Закупки товаров у поставщика за период

```sql
SELECT s.Name, SUM(line.Quantity * line.UnitCostIls)  -- или unitPrice в валюте документа
FROM PurchaseReceiptLines line
JOIN PurchaseReceipts r ON r.Id = line.PurchaseReceiptId
JOIN Suppliers s ON s.Id = r.SupplierId
WHERE r.TenantId = @tenant
  AND r.Status = 'Posted'
  AND r.DocumentDate BETWEEN @from AND @to
GROUP BY s.Id, s.Name;
```

### Детализация: накладная GR-000xx — из чего сложилась себестоимость

- Товарные строки: база + доля landed cost (можно сохранять `AllocatedLandedCostIls` на строке при Post — опционально фаза 2).

## 5. Что **не** делать

| Подход | Почему плохо |
|--------|----------------|
| Добавлять FedEx как услугу SV в товарные строки | Не увеличивает FIFO товара |
| Один `SupplierId` на всю накладную для FedEx | Нельзя отличить поставщика товара и логиста в отчётах |
| Ручной ₪/ед. без строк расходов | Нет отчёта по FedEx; теряется аудит |

## 7. Пример расчёта

Накладная от **Supplier China**, USD, курс 3.625:

| Товар | Qty | Сумма USD | База ₪ |
|-------|-----|-----------|--------|
| CP-001 | 100 | 120 | 435 |

Доп. расходы:

| Поставщик | Категория | Сумма |
|-----------|-----------|-------|
| FedEx | Logistics | 30 USD |
| FedEx IL | Customs | 228 ILS |

`totalLandedIls` = 30×3.625 + 228 = **336.75 ₪**  
`unitCostIls` = (435 + 336.75) / 100 = **7.72 ₪**

Отчёт по FedEx (международно): 108.75 ₪; по FedEx IL: 228 ₪.
