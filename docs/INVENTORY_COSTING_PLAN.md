## 2. Решения по валюте закупок (USD / ILS)

### Проблема
Инвойс в USD, банк списывает ₪ по **своему** курсу + комиссия. Курс «мирового рынка» ≠ курс банка.

### Рекомендуемая модель (практичная)

| Поле | Назначение |
|------|------------|
| Валюта накладной | USD / ILS (как в инвойсе поставщика) |
| **Цена в инвойсе** | `unitPrice` — в валюте накладной |
| **Себестоимость в ₪** | `unitCostIls` — **фактическая** стоимость единицы для склада и FIFO |

**Правило:** для FIFO и מלאי всегда используется **`unitCostIls` (₪)**.

Как заполнять `unitCostIls` при закупке в USD:

1. **Идеально (когда разберётесь с банком):**  
   `(сумма списания банка в ₪ + комиссия) / количество` по этой строке накладной.

2. **Пока нет данных банка:**  
   USD × **ваш усреднённый рабочий курс** (например, средний курс банка за квартал).  
   В заметках накладной — «курс ориентировочный, уточнить по выписке».

3. **На opening balance 31.12.2024:**  
   все суммы уже в **₪** (из старого отчёta).

Опционально на накладной (позже): поле «курс банка», «комиссия ₪» — для аудита, без автоматической привязки к API банка.

**Итог для отчётности в Израиле:** бухгалтер видит **только ₪**; валюта инвойса — справочно.

## 3. Готовые изделия (FG): производство vs закупка

| Ситуация | Тип товара | Приход | При продаже |
|----------|------------|--------|-------------|
| Собираете из комплектующих | FG / Bundle с BOM | комплектующие приходуются отдельно; FG **не** оприходуется на склад (`trackInventory = false`) | списание **только компонентов по BOM** (FIFO по каждому), FG не списывается |
| **Купили готовое изделие** у поставщика (USD/ILS) | **FG** (без BOM или BOM пустой) | накладная → склад **готовой продукции**, `unitCostIls` | списание только FG по FIFO |
| Купили комплектующее | CP / SP | склад комплектующих | списание при сборке/продаже |

**Совет:** закупленное готовое изделие — всегда **тип FG**, в накладной выбираете **склад готовой продукции**. Не нужно «разбирать» на компоненты, если вы его не производили.

Прибыль по FG:
- **Закупленное FG:** выручка − FIFO-себестоимость закупки.
- **Собранное FG:** выручка − (FIFO компонентов + при необходимости труд/накладные — позже).

## 4. Методы оценки

| Метод | Статус | Описание |
|-------|--------|----------|
| **FIFO** | **Основной** | Партии по дате прихода; списание из старых партий первым |
| **WAC** | Опция в настройках | Средневзвешенная цена; базовая реализация после FIFO |

Переключатель: **Настройки → Учёт склада → FIFO / WAC**.

## 5. Модель данных (технически)

### Новые сущности

- **`InventoryLot`** — партия: товар, склад, `qtyRemaining`, `unitCostIls`, `receivedAt`, источник (opening / purchase).
- **`InventoryLotAllocation`** — списание из партий при продаже (движение ↔ партия, qty, cost).
- **`InventoryAverageCost`** — кэш средней цены (WAC): товар + склад → `unitCostIls`.

### Расширения

- **`StockMovement`:** `movementDate`, `unitCost`, `totalCost`.
- **`PurchaseReceiptLine`:** `unitCostIls` (₪ для FIFO).
- **`Tenant`:** `inventoryCostMethod` (Fifo / Wac).

### Источники партий

| Источник | Когда создаётся |
|----------|-----------------|
| OpeningBalance | API начальных остатков на дату (31.12.2024) |
| PurchaseReceipt | Оприходование накладной (`receivedAt` = дата документа) |
